NOT COVERED BY THESE NOTICES
------------------------------------------------------------------------------

- DynDOLOD, TexGen, xLODGen and LODGen (sheson, zilav, Ehamloptiran and the
  xEdit team): LODForge contains no code from these tools and ships none of
  their files. It reads the LOD meshes, rule files, configuration and
  billboards installed in the user's own setup (DynDOLOD Resources, LOD packs,
  TexGen output) at run time, the way those tools themselves do. Their licenses
  (DynDOLOD Resources: CC BY-NC-SA; the tools: MPL 1.1 per their shipped
  license file) govern those files, not LODForge.
- The Elder Scrolls V: Skyrim Special Edition and its game data: LODForge
  reads the user's installed plugins and archives; it includes no game assets.
- Microsoft Edge WebView2 Runtime: the LODForge UI (Tauri) renders in the
  WebView2 runtime installed on the user's system. It is not distributed with
  LODForge.
- What LODForge generates: generated LOD files can contain other mods' assets
  (textures, meshes) and must not be redistributed without those authors'
  permission.
- Reference and golden data used during development (outputs of the reference
  tools, test profiles, reverse-engineering notes) are not part of the
  repository or the releases.

Corresponding Source for binary releases: every release carries the source
archive of the exact tagged commit (see docs/releases.md); third-party crates
are fetched by Cargo from crates.io at the versions pinned in Cargo.lock and
their source can be vendored with `cargo vendor`.
