# Historical roadmap (2026-10-17 to 2026-10-19)

Archived during the documentation review on 2026-10-19. This records the project's
development, not its current architecture or remaining work. Status statements below
can contradict later results. Start with the [current roadmap](../../PLAN.md),
[architecture](../architecture.md), or [parity assessment](../parity.md) instead.

A fast, automatable replacement for xLODGen (first) and DynDOLOD (later) for Skyrim SE.
Goal: cut LOD builds — especially with seasons — from hours to minutes, behind a guided UI
and a headless CLI that Cairn / skyrim-mcp can drive.

Decisions (2026-10-17): xLODGen parity first · Rust + wgpu + Tauri · private / personal + Cairn use.

## What we're replacing (survey, 2026-10-17)

| Component | What it is | How we get its behaviour |
|---|---|---|
| xLODGenx64.exe 4.1.5o | xEdit LOD mode, Delphi, **MPL 2.0, source on github.com/TES5Edit/TES5Edit** | Object/tree LOD: read the source (`Core\wbLOD.pas`). **Terrain LOD and seasons are not in the public repo**; they exist only in sheson's closed "Terrain LOD Beta" build, so they need an REA behavioural spec like DynDOLOD. |
| LODGenx64.exe 3.1.8 (DynDOLOD) / 3.0.36 (xLODGen) | Object + tree + **terrain** LOD mesh builder; **.NET Framework 4.8 IL-only**, MPL 1.1, ~1,600 methods; uses LZ4, SharpZipLib, s-hull Delaunay | REA `inspect_managed_artifact` → decompile; port to Rust. Input = LODGen export text file written by xLODGen/DynDOLOD. |
| DynDOLODx64.exe / TexGenx64.exe | Closed Delphi on xEdit; DynDOLOD assets CC BY-NC-SA | REA → **behavioural spec** (INI keys, rules/mesh-mask formats, output layout, ESP records DynDOLOD DLL NG + scripts expect). Clean-room implementation from the spec. Read the user's installed DynDOLOD Resources; never bundle them. |

Install under test: `D:\Modlists\skyrim-cs\tools\{xLODGen,DynDOLOD}`.
Host: i7-12700K (20 threads), RTX 4080 16 GB.

## Why seasons take hours

xLODGen regenerates **every selected worldspace in full once per season** (default + SPR/SUM/AUT/WIN),
and season swaps (`Data\Seasons\*.ini`, `base|swap` pairs) touch only some STAT/TREE/LTEX records.
Outputs are `*.[SPR|SUM|AUT|WIN].[btr|bto|btt|lst|dds]`.

Speedups, by expected payoff:
1. **Season delta builds.** Compute which LOD chunks reference a swapped base/LTEX; build only those per
   season; untouched chunks are copied/hardlinked from default. (The WIN snow-shader variant touches every
   object chunk, so it stays a full build, but shares all parsing/loading.)
2. **Load once.** Parse plugins, BSAs, meshes and textures once for all worldspaces × seasons
   (memory-mapped, parallel record decode) instead of per pass.
3. **Chunk-parallel CPU.** Every BTO/BTR/BTT chunk at every level is independent → rayon work queue.
4. **GPU (wgpu compute).** Terrain diffuse/normal rendering from LTEX + vertex colour; BC1/BC3/BC7 block
   compression; mip generation; later TexGen billboard rendering and occlusion rasterisation.
5. **Content-addressed cache.** Hash inputs per chunk → incremental rebuilds after a modlist change.

## Architecture

```
crates/
  esp       plugin/record reader (TES4 format, SSE), load order, form-ID resolution, LAND/LTEX/STAT/TREE/REFR/WRLD
  archive   BSA (SSE v105, LZ4) reader + loose-file VFS overlay (MO2-aware via profile + -d/-p args)
  nif       NIF read/write subset needed for LOD (BSTriShape, BSLODTriShape, shader props, BSMultiBoundNode)
  dds       DDS read/write, decode; BCn encode on CPU (fallback) and GPU
  gpu       wgpu device, compute pipelines (terrain bake, BCn encode, mips)
  terrain   terrain LOD meshes (BTR) + textures, heightmap, underside
  objlod    LODGen port: object LOD (BTO), atlas, terrain-clip optimisation
  treelod   tree LOD (BTT/LST, billboards)
  seasons   swap parsing, chunk-dependency index, delta planner
  occlusion Skyrim occlusion data (later)
  core      job graph / scheduler, cache, progress events, config (TOML preset)
apps/
  cli       `lodforge build --preset my.toml --profile <MO2 profile>`, JSON progress on stdout
  ui        Tauri: guided flow (detect game/MO2 → choose worldspaces → quality preset → seasons → review → build)
```

The job graph is the backbone: nodes = (worldspace, LOD level, chunk, season, artefact), edges = data deps.
The UI and the CLI both just submit a graph and stream events.

## Correctness strategy

Parity is judged against real xLODGen output, not by eye:
- Golden runs: xLODGen on `skyrim-cs` (Tamriel + a small worldspace, with and without seasons) → snapshot outputs.
- Diff tools: NIF structural diff (vertex count, bounds, shader flags, tolerance on positions), DDS PSNR/SSIM, byte-exact for `.lst`/text.
- In-game spot check via skyrim-mcp (`game_screenshot` / `image_compare`) at fixed camera positions.

## Phases

**P0 — Baseline & harness** (first)
- Scripted xLODGen runs (CLI args `-sse -o:` …) on skyrim-cs with timing per stage; same for DynDOLOD later.
- Golden output snapshots + diff tooling skeleton. Cargo workspace, CI-less `cargo test`.

**P1 — Foundations:** `esp`, `archive`, `dds`, `nif` readers; load skyrim-cs load order and list LAND/REFR per worldspace; benchmark parse-everything time vs xLODGen's startup.

**P2 — Terrain LOD:** done 2026-10-17 — BTR meshes (LODGen 3.0.36 port, decompiled with ILSpy) + diffuse/normal textures (REA spec of the xLODGen beta), GPU bake + BC7, season deltas. See docs/baseline.md.

**P3 — Object + tree LOD:** BTO builder done 2026-10-17 — LODGen 3.0.36 object path ported (atlas UVs + ReUV, terrain clipping, merging), chunk-parallel, all seasons in 2.8 s vs ~97 s LODGen; parity at LODGen's own run-to-run level (order-independent diff). LODGen 3.1.8 decompiled for P6. Export + atlas from the load order done 2026-10-17 (exact match to xLODGen for all 5 seasons; full object LOD 8.8 s vs 3:08). Tree LOD done 2026-10-17 (LST byte-identical, 388/388 BTT identical bar xEdit's random rotation, against a placeholder-billboard golden). Other worldspaces: terrain export identical for all 11, 1,271/1,274 BTRs byte-identical.

**xLODGen parity status (2026-10-17):** `lodforge build` runs terrain + objects + trees for all 15 LOD worldspaces × 5 seasons in 437 s (xLODGen: ~45 min for Tamriel's seasons alone), into a folder or an MO2 mod. Not yet done: an in-game check of the output.

**P4 — Seasons:** swap parsing, dependency index, delta planner; WIN snow shader. Headline benchmark: full 5-season build vs xLODGen.

**P5 — UI + automation:** Tauri guided flow; presets; CLI JSON events; skyrim-mcp / Cairn hook (`lodforge build` as a list step). Done 2026-10-17: `lodforge build --json`, `lodforge info --json`, Tauri UI (`apps/ui`, 5-step flow, verified end to end over CDP). Open: presets, Cairn step.

**P6+ — DynDOLOD track:** REA behavioural spec of DynDOLOD/TexGen (rules, mesh masks, dynamic LOD ESP records, grass LOD with No Grass In Objects cache, TexGen billboards, occlusion); implement in order of user value.

**P6 status (2026-10-17, branch `p6-dyndolod`):**
- Spec in docs/re/dyndolod-spec.md (clean room, confirmed against golden runs).
- LODGen 3.1.8 delta ported as `Flavor::Dyndolod318`, including .NET 8/10 System.Numerics
  emulation, `LimitCoords`/`LODCoords` season copying, `VC` and AltTextures.
- Golden TexGen (2:04) and DynDOLOD Medium/Tamriel/seasons (6:59) runs are in docs/baseline.md.
- `lodforge object-lod --flavor dyndolod` rebuilds DynDOLOD's own exports, 5 seasons in 10 s:
  - 685/685 files per season;
  - 40.5% of triangles bit-identical, 71.0% within tolerance.
- `crates/nif` reads Skyrim LE (NiTriShape) meshes.

**P7 status (branch `p7-dyndolod-gaps`):**
1. LODGen-side gaps: done. FlatTextures billboards, MergeVertexColors, the RemoveUnseenFaces
   heightmap stage and passthru effect shaders are ported; the HD naming case is LODGen thread
   order (docs/baseline.md "P7"). DynDOLOD exports rebuild at 98.44% of golden triangles within
   tolerance (52.1% exact), 2/685 files with different shape sets.

2. DynDOLOD export written by LODForge (`dyndolod-export`, crate `lodforge-dyndolod`): rule table
   exact; 31,425/34,590 reference lines and 153/155 header lines byte-identical; season exports
   with LODCoords; FlatTextures 116/123. Open: LimitCoords, child-world copies, the MNAM rule,
   AltTextures/VC/atlas/mini-atlas files.
3. TexGen tree billboards on the GPU (`texgen-billboards`, crate `lodforge-texgen`): 64 of 127
   rendered, 30 at the golden size, 20.95 dB. Open: skinned NiSwitchNode foliage, normal bake.
4. Grass LOD: `.cgid` reader, grass statics, per-placement replication, `grass-billboards` and
   `object-lod --grass`. Against the DynDOLOD grass golden (2026-10-18), 99.952% of LOD4
   triangles are identical within tolerance, with 2/499 files having different shape sets
   (FlatTextures NIF templates ported). DynDOLOD's grass reduction is the TexGen type filter
   (32/46 types, 53% of placements) plus `GrassDensity`, which defaults to 100%. At that default
   its LOD4 is 8.7 GB. `grass-billboards` now applies TexGen's type rule (OBND magnitude >= 64,
   z2 >= 32, model bounds when OBND is zero, not below water): same 32 map keys as DynDOLOD.
   `object-lod --grass-density` defaults to the export's `GrassDensity`, else 50% (3.6 GB LOD4);
   parity passes 100. Open: a density control in the UI, and the CS Grass Optimizations assets.
5. DynDOLOD.esm/.esp + DLL NG data files: plugin writer and dynamic LOD selection (1,646/1,671
   golden originals found, plus extras); QUST/VMAD, markers and ESM workarounds missing; untested
   in game.
6. Occlusion (`lodforge occlusion`, REA pass on DynDOLOD's TVDT code): all 6,285 golden TVDT
   identical in all 8 worldspaces, Occlusion.esp record-for-record equal except WRLD OFST byte
   offsets (we write uncompressed records); 8.7 s vs ~2 min. Still needs LODGen's
   `objects.heightmap.dat` (CreateHeightMap, not in objlod yet) and the run's DynDOLOD.esm/.esp;
   not tried in game.
All numbers are in docs/baseline.md "P7".

**P8 status (branch `p8-texgen-parity`): TexGen billboard parity.** Numbers in docs/baseline.md "P8".
1. Geometry: done. 126/126 golden tree billboards render (TexGen draws non-skinned shapes
   including SSE NiTriShape/BSLODTriShape, ignores switch indices, and uses DynDOLOD's
   `Replace\*_static.nif`). 62 at the golden pixel size, 19.89 dB.
2. Size and framing: TexGen's rules are in (p0 rounding, x-range pre-pass, anisotropic
   sampling, vertex alpha ignored, unmulta test, culling). 74/126 at the golden pixel size,
   111/126 within 4 px, ShiftZ within 1 unit 111/126, 94.1% alpha agreement: below the 90%
   size target because of rasterisation noise (8x MSAA vs TexGen's 16x GL), see baseline.
   Depth 35/126 (TexGen's own Depth is not deterministic per model).
3. Shading: TexGen's light model with normal maps, specular/emissive/soft/rim terms, PBR
   scale and radius-2 bleed. 25.25 dB on golden-opaque texels (25.53 dB where both are opaque,
   30.38 dB on 4x4 block means), 94.1% alpha agreement: below the 30 dB / 97% targets because of
   per-texel foliage noise; six snow pines at 12..14 dB are unexplained (see baseline).
4. Outputs: `_n` bake, two-view rendered billboards (119/119 trunks at 27.65 dB, 97.5% alpha,
   rendered from the back), HD grass (79/79, 29.66 dB), full sidecars (Model, ModelCRC32, texture
   set and CRCs equal for all 324 golden billboards). Open: `_n` PSNR 19.5 / 22.5 dB, trunk twigs,
   32 px grass sizes.
5. Batching and `build`: done. Two GPU round trips per batch of 32, texture cache: 126 tree
   billboards in 3.2 s (P7: 10.5 s for 64). TexGen discovery from the load order (489/489
   candidates, same 126 accepted, identical report). `lodforge build --texgen` runs it before tree
   LOD (5.5 s for Tamriel incl. 119 trunks).

**MVP status (branch `build-mvp`, 2026-10-18): `lodforge build --mode dyndolod`.** Numbers in
docs/baseline.md "MVP".
- One command (and the UI) chains the build's own DynDOLOD export → object atlas → object LOD +
  height map → tree LOD → DynDOLOD.esm/.esp + DLL NG data → Occlusion.esp, with no DynDOLOD
  output or golden as input; earlier LOD output in the profile is left out automatically.
- Against the E2E DynDOLOD reference (Tamriel): non-grass object LOD geometry 94.2% / 92.2% /
  82.8% (LOD4/8/16), grass 93.1%; dynamic LOD finds 99.0% of DynDOLOD's references; Occlusion.esp
  covers the same 5,697 Tamriel cells (Jaccard 0.9955; the reference's terrain LOD input is gone).
- Grass: `--grass go` writes Grass Optimizations `_lod1.nif` meshes (no cache); `--grass bto` does
  DynDOLOD's grass LOD from the NGIO cache, remapped to the current load order, or from generated
  placements where there is no cache.
- Runtime iteration: DynDOLOD.esp carries the DLL NG framework (version keyword, activators,
  init/MCM quests with VMAD); dynamic LOD matches DynDOLOD's selection (2,958, all in golden,
  96.1% of it); `[Objects]` lines follow DynDOLOD.DLL's parser; child-world occlusion fixed.
- Full headless build of LODForge-E2E (15 worldspaces x 5 seasons, TexGen, DynDOLOD mode, GO
  grass meshes): 417 s, 0 failed stages. Nothing of it has been tried in game yet.

**Own LOD resources (branch `own-lod-resources`, 2026-10-18): no DynDOLOD Resources needed.**
Inventory, licensing and design in docs/re/own-lod-resources.md, numbers in docs/baseline.md

In-game LOD checks: put the player under the camera (`cow`/`coc`). With a free camera far from
